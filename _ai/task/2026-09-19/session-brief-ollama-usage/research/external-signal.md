# External signal

- Ollama’s official Cloud documentation says hosted cloud use is available through `ollama.com`, links users to a Usage settings page, and distinguishes the local Ollama app/CLI from direct cloud API access: [Cloud](https://docs.ollama.com/cloud), current as fetched 2026-09-19. **Approach impact:** the current loopback-only probe cannot establish cloud plan usage.
- Ollama’s official authentication guide says the local API does not require auth, direct `https://ollama.com/api` access requires an API key, and hosted API requests use `Authorization: Bearer ...`: [Authentication](https://docs.ollama.com/api/authentication.md). **Approach impact:** use a read-only Bearer request; do not scrape cookies or send a raw key by default.
- Ollama’s API introduction documents separate base URLs for the local server and direct hosted cloud API: [API introduction](https://docs.ollama.com/api/introduction.md). **Approach impact:** the cloud adapter must use the hosted origin rather than treating `/api/me` on loopback as a cloud account query.
- The official public API usage page documents generation metrics, not the account quota response: [API usage](https://docs.ollama.com/api/usage.md). **Approach impact:** one sanitized authenticated runtime check is the source for the account-quota shape below; the implementation should still parse the response defensively because the public page does not define it.
- OpenCode’s current auth implementation stores auth data at `Global.Path.data/auth.json`, models API credentials as `{ type: "api", key: string }`, and filters/reads the JSON without exposing unrelated fields: [auth/index.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/auth/index.ts#L9-L50). Its provider code also consumes API auth through `auth?.type === "api" ? auth.key`: [provider.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/provider.ts#L620-L630). **Approach impact:** the one in-process check confirmed the matching entry is `ollama-cloud` with type `api`, so the repo’s existing read-only auth-file pattern can supply the key without changing storage or refresh behavior.
- On 2026-09-19, one sanitized in-process check made one authenticated `GET https://ollama.com/api/usage` and received HTTP 200. It observed `limits.session` and `limits.weekly` as objects, with numeric `usage` fields whose range was fraction-like 0–1. No reset fields appeared in either period object. Exact values and the key were discarded, and no retry occurred. **Approach impact:** the preferred adapter can map the two fields to `UsageWindow` values by multiplying by 100 and clamping, with `resetsAt: null` for this response shape.
